# How to Propose Changes (Project Rule)

All proposed changes to UI, logic, terminology, or structure must be evaluated against:

- `DOCS/DEPRECATED_TERMS.md`
- `DOCS/ADVANCED_MATCH_OPTIONS_UI_MAPPING.md`

Before a change is accepted, it must be demonstrated that:
1) No deprecated terms, systems, or mental models are reintroduced.
2) The proposal can be expressed entirely within the existing canonical layers
   (Learning Type, Input Method, Domain Constraints, Surface Controls, Match Rules).
3) The proposal does not collapse multiple layers into a single control.

If a proposal cannot meet all three conditions, it is non-compliant and must be revised
or rejected. This rule exists to prevent regression, ambiguity, and repeated re-litigation.
